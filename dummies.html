Fast Dummies

Overview

This document demonstrates the creation of dummy variables for categorical data and explores the implications of choosing different reference groups in regression analysis.

Setup

First, ensure all required packages are installed:

# Load required packages
library(fastDummies)
library(haven)
library(dplyr)

Load and Explore Data

# Load the admissions data
admissions <- haven::read_sav("data/admissions.sav")

# Examine the Race variable
table(admissions$Race)

American_Indian           Asian           black        Hispanic   not_indicated 
              3              59              69              15              21 
          white 
            713

Data Preparation

Filter out cases where race is not indicated:

admissions_sub <- admissions %>%
  dplyr::select(row_number, Race) %>%
  filter(Race != "not_indicated")

table(admissions_sub$Race)

American_Indian           Asian           black        Hispanic           white 
              3              59              69              15             713

Creating Dummy Variables

The Wrong Way (Automatic Removal)

The fastDummies package can automatically remove the first dummy variable, but this can lead to unintended consequences:

# This approach removes the first category automatically
admissions_wrong <- fastDummies::dummy_cols(
  admissions_sub,
  select_columns = "Race",
  remove_first_dummy = TRUE,        # creates k-1 dummies
  remove_selected_columns = FALSE    # if TRUE drops original race variable
)

# Inspect result
head(admissions_wrong)
names(admissions_wrong)

What do you notice? The function removed the first variable, which was Native American. This is problematic because:

  1. We may not realize which category was dropped
  2. The dropped category may have too few cases
  3. We lose control over our reference group

The Better Way (Keep All Variables)

It’s better to keep all dummy variables and explicitly control which one to omit in regression:

# Create dummy variables WITHOUT automatic removal
admissions_sub <- fastDummies::dummy_cols(
  admissions_sub,
  select_columns = "Race",
  remove_first_dummy = FALSE,        # Keep all dummies
  remove_selected_columns = FALSE    # Keep original race variable
)

Handling Small Group Sizes

When a category has very few observations (like American Indian in this dataset), it may be appropriate to exclude those cases:

# Remove American Indian students due to small sample size
admissions <- admissions %>% filter(Race_American_Indian != 1)

# Re-run model
summary(mod <- lm(SAT_math ~ SAT_verbal + HS_class_size + Race_Asian + 
                    Race_Hispanic + Race_white, admissions))

Comparing Specific Groups

How would you compare Asian and White students?

To compare Asian and White students directly, you have several options:

Option 1: Coefficient Interpretation

In the model above, both Race_Asian and Race_white coefficients are relative to Black students (the reference group). To compare Asian to White students:

  • Calculate the difference: Race_Asian coefficient - Race_white coefficient
  • This gives you the Asian vs. White effect, holding other variables constant

Option 2: Change the Reference Group

Make White students the reference group by excluding Race_white:

summary(mod <- lm(SAT_math ~ SAT_verbal + HS_class_size + Race_Asian + 
                    Race_Hispanic + Race_black, admissions))

Now Race_Asian directly represents the difference between Asian and White students.

Option 3: Use Contrast Coding

For formal hypothesis testing of Asian vs. White differences, consider using contrast coding or post-hoc comparisons.

Key Takeaways

  1. Always know your reference group - Don’t let software automatically choose it
  2. Consider sample sizes - Small groups may need special handling
  3. Think about interpretation - Choose a reference group that makes sense for your research question
  4. Avoid the dummy variable trap - Use k-1 dummies in regression models
  5. Be explicit - Manually control which variables to include rather than relying on defaults
